# 本机 NLP 行为基线

日期：2026-09-21。开发阶段 P0 的来源观察；P1–P4 依此确定适配、对齐、分析单元和应用词法协议。

## 语料与复现

指定语料 `data/validation/refractor_source.txt` 共十段，依次包含政治史叙述、文语气象描写、拟人叙述、法律条文、文库告知、新闻采访、气象新闻、议论、口语缩略与人物心理叙述。覆盖旧字形、专名、数字、括号、嵌套引语、长句、拟态词及连续活用。

本轮选择第六、九段、第二段首句、第四段，增加空白与 Unicode 边界、跨句照应、活用三组短例，共七组。边界例中的 `ｶﾞ`、`が`、`㍿`、`𠮷` 分别检查收缩、组合、展开和补充平面字符。未进行小说全文分析。

```powershell

experiments/kwja311/Scripts/python.exe -X utf8 scripts/probe_nlp_behavior.py kwja
cargo build -p kotoclip-core --bin kotoclip-nlp

```

可以用 `--cases news contraction` 限定片段。机器证据保存在 `data/validation/behavior/`，包括输入、来源版本、模型原始字段、KNP 原文和本轮耗时。UniDic 在同一进程内分别请求 CWJ、CSJ；GiNZA、KWJA 各自加载一次模型并连续分析七组文本。

## 输出性质与设计决定

### 正文及坐标

GiNZA 的 `doc.text` 在全部样本中与输入一致，token 的 `idx` 是 Python 字符坐标。空白既可能成为 `is_space` token，也可能保存在前一 token 的 `whitespace_`。边界样本末尾空白独立形成 token 和文节候选，应用正文与模型结构需要分别保留。

KWJA 的 `_normalize_text` 先执行 NFKC，再将普通空格变为 `␣`，删除换行、制表符等控制字符，并处理引号、井号和插值文本。新闻中的 `（２８）` 输出为 `(28)`；边界样本的 `ｶﾞ`、`が` 分别变为 `ガ`、`が`，`㍿` 展开为 `株式会社`。直接在输入中搜索模型表面串会漏掉这些 token。适配器应按实际规范化操作建立来源映射，同时保存原文跨度、规范化跨度和模型表面串。一个原文字符可能对应多个模型 token，多个原文字符也可能对应一个模型字符。

UniDic 的 gap 包含制表符、换行和半角空格；边界样本末尾 `[28,31)` 是合法 gap。现有采集脚本按最后一个 token 的结束位置判断截断，会错误拒绝该样本。完整覆盖应检查 token 与 gap 的并集。完整正文长度和摘要应独立于 token 结束位置保存。

### 词法与活用

GiNZA 的 Sudachi `sub_tokens` 保存 A／B 模式分解：`神戸市`、`会社員`、`警察署` 有短单位成分，`見渡す` 分为 `見／渡す`。空白项为 `None`；`㍿` 的分解可能只有一个成分。构词候选需要核对成分数量、坐标与词典证据。

UniDic 在活用样本中输出 `見え／なかっ／た`、`記録／さ／れ／た`、`読ん／で／くださっ／た`、`静か／な`，提供应用活用链的词法基础。KWJA 将 `なかった`、`れた`、`読んで`、`くださった` 作为较长的形态素，适合通过字符范围建立多对多关系。

KWJA tiny 的实测输出存在词法错误，例如 `買った` 的 lemma 为 `買っる`、`読んだ` 的 reading 为 `かった`、`静かな` 标为イ形容詞。UniDic 负责查询形、读音和个人词汇身份；KWJA 字段作为独立来源证据供查看，应用决定保存来源及理由。

### 主辞、依存与语义

GiNZA token 的 `head` 指向依存目标；文节 `root` 是内部主辞。例如 `雨が` 的主辞为 `雨`，依存目标为 `降る`。当前转换器将 token.head 写入 `head_char_range`，混淆了两者。协议应分别保存内部主辞引用和有标签的依存关系。

GiNZA 小句使用词元成员集合，来源于依存子树及边界规则；保存成员和实际范围能表达可能不连续的结构。句界对引号内句号有自身判断，例如新闻样本分成三句，KWJA 分成两句。应用选择策略需要保留两份结果和引号上下文。

KWJA 的 `*` 是文节，`+` 是基本句，`節-主辞／節-区切` 支持小句。新闻样本中同一文节内存在多个基本句；三种对象需分别建模。文节和基本句的 parent_index 均为句内索引，解析后应转换为稳定的来源实体引用。

KWJA `rel` 标签实际包含格关系、外指及照应。例如 `買った` 的ガ格指向 `太郎`、ヲ格指向 `本`；下一句 `彼` 的 `=` 指向前句 `太郎`。外指 `著者`、`不特定:人` 没有正文范围。模型同时将 `それ` 指向 `買った`，说明来源关系和应用采纳决定需要分开。解析应使用 rhoknp 对象，保留原始标签及外指类型；现有逐行采集器遗漏全部 `+` 与 `rel` 内容。

KWJA word 模块具有独立任务集合，能力登记应读取实际加载 checkpoint 的任务配置。关系集合为空表示该文本未产生相应关系；任务是否启用由能力状态表达。

### 分析单元与语域

新闻样本以 CWJ 请求，当前路由因为长引语选择 CSJ，导致叙述部分同时切换。单元策略应区分请求语域、实际选择和上下文类型，并保存选择理由。KWJA 跨句照应需要同次输入提供相邻句，单元边界应保留合理的句段上下文。章节跳转与范围调度需要记录这些上下文依赖。

## 实施验收重点

P0：固定上述七组来源证据及版本，统一正文身份、来源能力、原始实体与关系协议。

P1：同进程复用模型，原始输出经适配后覆盖已启用任务；离线初始化、请求身份、取消、超时和重启有实际结果。

P2：按规范化映射恢复坐标；完整覆盖包括 gap；部分 token、展开映射、重复句、跨句关系和外指分别验证。

P3：按句段及引号上下文调度，验证语域选择、目标范围优先、代次与缓存一致性。

P4：活用链与查询消费 UniDic 证据；词典整体、来源结构、模型分歧和用户决定分别保存，解释范围引用准确成员。
