# 阅读器 Engine 与查询投影

本文定义 P6–P7 阅读器阶段使用的应用级 Engine、全文分析生命周期、NLP 进度和词典气泡投影。P4–P5 尚未完成的表达识别、语法扩展、词典筛选和排序保留后续接入点，当前阅读器依赖已经验证的 UniDic、GiNZA、活用链、整体构词和词典查询接口。

## 设计目标

阅读器 Engine 负责协调书籍、正文坐标、分析会话、词典查询和用户状态。UniDic 与 GiNZA 的分析逻辑继续由 `AnalysisService` 和 `DocumentSessions` 执行；Engine 负责将它们组织为可持续的书籍阅读流程。

完整流程如下：

```text
书籍或文本输入
    ↓
导入与正文准备
    ↓
阅读文档与字符坐标
    ↓
DocumentPlan
    ↓
DocumentSession
    └─ 各单元独立完成 UniDic、GiNZA、来源统一、整体构词与查词目标
    ↓
阅读投影
    ├─ 书籍正文
    ├─ 阅读胶囊
    ├─ 词典气泡
    └─ 用户状态与导出
```

各单元只有在 UniDic、GiNZA 和来源统一完成后才发布完整产物。未完成单元保持普通正文；已完成单元支持胶囊、查词和交互。来源失败时保留失败状态与重试入口。

## 生命周期

### 应用层

Tauri 启动时创建一个应用级 `ReaderEngine`，持有以下长期资源：

| 对象 | 职责 |
| --- | --- |
| `AnalysisService` | UniDic、GiNZA、文档会话、分析缓存和词典查询 |
| `ReaderLibrary` | 书籍、章节、图片资源、书架组织和阅读进度 |
| `ProfileEngine` | 词汇曝光、已知状态、汉字知识和用户词典设置 |
| 当前阅读会话 | 当前书籍、正文文档、分析会话、阅读位置和查询状态 |

应用级 Engine 统一管理启动、切书、关闭、重启恢复和用户操作。单个查询引用当前阅读会话中的分析单元和产物版本。

### 书籍层

书籍从书库读取后经历以下状态：

```text
closed → opened → preparing → analyzing → readable → complete
                                      └──────→ failed
```

- `opened`：已读取 `LibraryBook`，正文和资源路径可用。
- `preparing`：编译 Markdown、整理 ruby、建立章节／图片锚点和 Unicode 字符范围。
- `analyzing`：已创建 `DocumentSession`，按计划调度正文单元。
- `readable`：阅读位置所在单元的完整分析已发布，阅读和查词可用。
- `complete`：全文计划单元的完整分析已结束。
- `failed`：存在失败单元；已完成单元继续显示，失败单元保留重试入口。

切换书籍时，Engine 按以下顺序处理：

1. 保存当前字符偏移、章节、阅读时长和用户选择。
2. 关闭当前 `DocumentSession`，使旧查询引用失效。
3. 打开目标书籍并编译阅读文档。
4. 以书籍 ID 和正文文本版本创建新的 `DocumentSession`。
5. 请求保存位置附近的分析范围，优先生成可见正文。
6. 恢复滚动位置，并在后台继续全文分析。

书籍打开命令只读取 `LibraryBook` 并结束旧会话；前端先进入阅读加载状态，再由 `document.worker.ts` 编译正文，随后按保存位置创建 `DocumentSession` 并调用 `continue_document`。正文准备和语言分析均通过独立工作线程执行，阅读界面持续显示完整单元数；词典目标只为可见正文范围请求。

### 文档会话层

`DocumentSession` 由后端持有，前端通过 `open_document`、`poll_document`、`request_range`、`continue_document`、`cancel_document`、`retry_document` 和 `close_document` 操作。

单元状态采用完整产物原子发布模型：

```text
pending → processing → complete
                  └──→ failed
```

| 状态 | 实际工作 |
| --- | --- |
| `pending` | 等待调度 |
| `processing` | 在同一个单元任务内完成 UniDic、GiNZA、来源对齐、活用链、整体构词和查词目标 |
| `complete` | 完整 `UnifiedDocument` 已原子发布，可阅读和交互 |
| `failed` | 当前单元记录错误，其他单元保持可用 |

单元任务记录本次处理耗时 `elapsed_ms`；`generated_ms` 和 UniDic、GiNZA、来源统一、查词目标的分项耗时保存首次生成的数据。缓存命中时可比较读取耗时与原始生成耗时。阅读界面可切换诊断并导出单元 JSON。完整产物与查词目标按正文、来源配置、词典资源及模型资源身份写入磁盘缓存，切换耗时开关不会再次生成结果。

控制操作会提升 `generation`。迟到结果必须经过会话 ID、文本版本、任务代次和产物版本校验后才可进入阅读器。当前单元重新分析后，旧的 `artifact_revision` 立即失效，前端从最新单元状态重新建立查询目标。

### 查询层

词典查询是当前阅读会话的短生命周期对象：

```text
指针或点击 → 阅读投影目标 → 当前分析单元 → 查询目标 ID → 词典矩阵查询 → 气泡显示状态
```

查询请求携带 `session_id`、`text_version`、`generation`、`unit_id`、`artifact_revision` 和目标 ID。查询响应必须匹配当前目标；书籍切换、分析重算或单元卸载后，旧响应直接结束。

## 当前分析管线

阅读器使用已验证的当前管线。

### 准备阶段

EPUB、Markdown 和纯文本输入统一为阅读正文，建立书籍 ID 或独立文本 ID、正文文本版本、Unicode scalar 字符范围、原始文本与准备文本的映射，以及章节、图片和 ruby 锚点。准备结果同时服务正文渲染和 `DocumentPlan`，阅读器与 NLP 使用同一份字符坐标。

### 单元完整分析

每个正文单元执行以下工作：

1. 根据 CWJ／CSJ 路由选择 UniDic 来源。
2. 生成正式 token、词性、表记、读音、基本形和原始字段。
3. 请求 GiNZA 结构来源，并校验来源身份和字符范围。
4. 统一生成活用链、整体构词、对齐关系及查询候选，并构建该单元的查词目标。
5. 原子发布完整产物和查词目标，并写入磁盘缓存。

UniDic 是阅读器的词法主来源。词典查询使用 UniDic 的出现形、基本形、读音和活用链规范形式；词典结果不改变原始分析对象。

GiNZA 的“整体”只在具有合法字符范围、成员关系和结构证据时进入阅读器的整体显示投影。来源诊断继续保存，无法表达为阅读目标的实验结果保持在分析产物中。

## 分析进度

阅读器进度按完整单元统计，单元内部阶段只保留在耗时诊断中。

### 进度对象

```ts
interface ReaderAnalysisProgress {
  phase: "preparing" | "processing" | "completed";
  totalUnits: number;
  completeUnits: number;
  failedUnits: number;
  pendingUnits: number;
  activeUnitId: string | null;
  percent: number;
  message: string;
}
```

后端保留 `progress.total`、`basic`、`complete`、`failed` 和 `pending` 字段；`basic` 表示仍在内存中保留完整产物的数量，`complete` 表示已经完成的数量。前端计算将准备分析计为固定 3 份，每个完整分析单元计为 1 份；界面仍显示简短阶段文字和分析单元数量。

总进度计算为：

```text
preparing: 0%
processing: (3 + completeUnits) / (3 + totalUnits)
```

首屏关联单元达到 `complete` 后进入阅读，全文继续按单元完成度更新。取消分析时，已发布产物保持可用；滚动到内存中已释放的范围时，从完整缓存恢复相应单元。

## 词典气泡投影

词典气泡以词典验证后的外层词汇目标为基本显示单位，并保留该范围内全部可查询的内部组分。活用链附着在所属词汇目标上。

### 显示外围整体

每个阅读位置最多归属于一个当前显示外围整体：

1. 在合法边界内选择词典确认的最大合理词汇范围作为外层范围，GiNZA 整体提供结构证据。
2. 外层范围内的 UniDic token 和活用链成分归入该范围，同时保留各自可查询的词汇目标。
3. 没有成立整体词条的独立词，以自身词汇范围作为外层范围。
4. 标点、空白和跨越非法边界的来源成分不加入外层范围。
5. 活用链附着在所属核心词或功能词上，不单独制造新的外层显示框。

外层显示对象是“整体词／独立词 + 其活用链成员”的阅读查询单元。

正文胶囊根据已确认的整体词与词汇链建立边界，附属活用链归入所属胶囊。文节提供结构信息；标点和空白保持普通正文排版。

### 核心词

| 类型 | 核心词数量 | 默认查询对象 |
| --- | --- | --- |
| GiNZA 整体 | 1 个或多个 | 当前整体的核心词集合 |
| 非整体独立词 | 1 个 | 该独立词 |

整体可能包含多个具有独立词典意义的组分。悬浮时并排显示整体词条和当前位置对应的最小可查询组分；移动到其他组分时只更新内部面板。同一目标的整体与内部结果合并显示。

核心词对象至少保存 `target_id`、`char_range`、成员 token 范围、`surface`、`base_form`、读音、核心词角色、所属整体 ID、活用链 ID 和可用查询形。

### 活用链展示

存在活用链时，词典气泡右上展示整体形式名称、实际表记、基本形式、活用形和组成还原。当前词条的完整释义仍由词典气泡展示：

```text
出现形式 → 基本形式 → 活用连接
```

悬浮在活用部分时，形态 occurrence 的命中范围打开独立的说明气泡，与词典气泡并列。说明气泡呈现该部分的形式、作用、规范形式和已有候选含义；词典气泡继续查询所属核心词。表达和语法后续采用同一个说明气泡容器及其对应的分析对象。内部 `operator`、状态和来源证据继续保存，用户界面采用通用术语和简短说明。

### 悬浮与点击行为

悬浮行为固定为当前位置的整体与组分查询：

1. 指针进入显示外围整体或其活用部分时，定位所属核心词；活用部分的命中可延伸到外围词汇查询范围之外。
2. 延迟触发外层词汇目标与当前位置组分的词典查询。
3. 词典气泡右上显示整体活用概要；进入活用部分时，并列显示该部分的说明气泡。
4. 两个面板分别显示词典矩阵和释义，并各自保存表记、词典选择及请求代次。
5. 单击当前位置保持相同的目标组合。分析产物更新后，两个面板根据最新投影重新定位，旧目标自动失效。

### 查询目标层级

阅读器至少提供以下目标类型：

| 目标类型 | 范围 | 作用 |
| --- | --- | --- |
| `ginza_whole` | 词典确认的整体范围 | 外层显示和整体查询 |
| `independent_word` | 未被整体覆盖的独立词 | 非整体默认查询 |
| `core_word` | 整体或独立词中的核心词 | 当前悬浮位置的内部查询 |
| `morpheme_token` | 底层 UniDic token | 最小组分查询 |
| `morphology_chain` | 核心词附带的活用链 | 用户可理解的形态说明和规范查询 |

词典查询服务接收目标的范围、成员、查询形、读音、词性和来源证据。查询聚合、词典筛选和排序沿用当前引擎接口；P4–P5 剩余的高级决定规则以后通过目标投影扩展。

## 用户状态与导出

用户操作在阅读器 Engine 中统一处理：标记已知或未知、记录曝光、选择词汇、添加笔记，以及导出词形、读音、释义来源和上下文。

用户状态以词元知识身份和正文出现锚点保存。阅读位置以书籍 ID、文本版本、章节 ID 和字符偏移保存。分析重算后，正文出现锚点优先通过文本版本和字符范围恢复；无法恢复时保留原记录并提示用户重新定位。

## 实现入口与验收

应用级协调入口为 `src-tauri/src/reader_engine.rs`，Tauri 命令在 `src-tauri/src/lib.rs` 注册。核心依赖为 `crates/kotoclip-core/src/analysis.rs`、`crates/kotoclip-core/src/document_session.rs`、`crates/kotoclip-core/src/library.rs` 和 `crates/kotoclip-core/src/profile/`。阅读器投影位于 `src/components/reader/`，查询目标和词典矩阵位于 `crates/kotoclip-core/src/dictionary/targets.rs` 与 `src/types/nlp.ts`。

运行 `cargo build -p kotoclip-core --bin kotoclip-nlp` 后，可用 `python -X utf8 scripts/test_reader_pipeline.py` 生成冷启动、重启缓存、关闭耗时诊断和查词验证报告，默认写入 `.agents/analysis/reader-pipeline-test.json`。阅读界面的“导出耗时”可保存当前书籍每个单元的诊断数据。

验收顺序如下：

1. EPUB 或 Markdown 导入后创建书籍和阅读文档。
2. 首屏单元完成 UniDic、GiNZA 和统一处理后进入阅读，全文在后台继续分析。
3. 词典确认的最大合理词汇范围与未覆盖独立词形成显示外围整体。
4. 悬浮时并排查询外围整体和当前位置的最小可查询组分，活用链以规范形式和连接信息展示。
5. `三味線` 的 `三味`、`線` 均可访问；`茶屋酒` 默认包含整体词条。
6. 取消、重试、切书和重启恢复不会使用过期查询目标。
7. 阅读位置、已知状态、选择、笔记和导出经过重启验证。
