# 书库与阅读器

## 输入流程

EPUB 导入依次解析 container、OPF、spine、导航与 XHTML，提取正文、章节、作者注音和图片，保存原书及规范 Markdown。Markdown／文本输入进入同一正文准备和阅读文档协议。

导入阶段在保有 EPUB 语义时识别目录、章节头图和正文次序，清理设备提示、导航残片和展示属性。图片保存为独立资源，异常内容产生可查看的导入诊断。

Markdown 编译生成标题、段落、图片等阅读块，再形成分析正文及来源映射。标题清理、ruby 处理和空白规则在建立字符锚点前完成。前后端共享坐标样本，正文、章节、图片和语言分析均按准备后的字符位置关联。

## 书库与持久化

默认书库位于 Windows 文档目录的 `Kotoclip Library`。书籍目录按 EPUB 内容摘要生成稳定 ID，重复导入复用原书与已有进度。

```text
Kotoclip Library/
  library.sqlite
  books/<book-id>/
    source.epub
    content.md
    assets/
```

SQLite 保存书籍元数据、章节、资源相对路径、颜色与标签、阅读偏移和累计时长。原书、正文和图片作为普通文件保存。数据库迁移使用版本化事务，应用更新保留用户书库及个人数据。

导入过程校验资源后写入书籍目录并提交索引；失败时报告具体阶段并清理本次临时产物。删除通过书库内暂存目录与数据库事务协调，失败时恢复书籍目录。

## 书架

书架提供导入、最近阅读、搜索、排序、颜色与标签分类、详情、重置进度、删除和打开书库目录。继续阅读恢复书籍、章节和字符位置。长书名与空书架拥有完整可用布局。

独立文本输入使用相同阅读器和语言服务；其会话与书籍身份分别管理。引导界面负责进入书库、文本输入和必要的本机资源配置。

## 阅读投影

阅读器接收正文块、阅读单位、注音、颜色、语法与表达标记以及解释目标。语言学判断由后端产物提供，前端负责布局、命中和用户操作。

阅读胶囊保留内部成分与整体入口；拖选生成实体和范围选择，可用于查询、收藏或导出。图片和章节标题与正文共同组成异构虚拟行。

默认分组消费下一模块的词汇选择与语法目标。每个位置可访问合理整体、内部子词和最小查询成分；视觉分组保留较小目标的独立命中范围。先在 P5C 短文本界面验证粒度切换，P6 复用相同目标处理跨章节坐标、虚拟滚动及增量更新。

虚拟列表使用 `@tanstack/vue-virtual`，按可见范围创建文本与图片节点。分析更新、图片加载和排版修改触发行高测量。选中状态以出现锚点保存，虚拟行索引用于布局。

## 章节与进度

章节跳转先请求目标附近的分析范围，再根据字符锚点滚动。阅读进度采用当前字符偏移与总正文字符数计算；字体、图片高度和虚拟行重新测量保持进度语义稳定。

滚动停止后合并写入进度，离开阅读页面和关闭会话时提交最终位置。重启后先恢复目标附近正文，再恢复滚动位置。阅读时长和预计完成时间作为辅助信息显示。

字号、行距、段距和版心宽度保存为本机偏好。正文优先占用可用空间，导航、排版和开发诊断按需展开。

## 验收与入口

验收覆盖多章节 EPUB、目录头图、连续 ruby、首章以后的坐标、混合空白、补充平面字符、图片缺失、长文本跳转、取消分析和重启恢复。书架操作、排版设置、查词及选择操作在实际 Tauri 窗口共同验证。

[epub.rs](../crates/kotoclip-core/src/import/epub.rs)提供导入基础，[library.rs](../crates/kotoclip-core/src/library.rs)提供书库存储，[document.ts](../src/reader/document.ts)和[reader_markdown.rs](../crates/kotoclip-core/src/reader_markdown.rs)提供正文编译基础。界面组件位于 [reader](../src/components/reader/)，应用协调入口为 [App.vue](../src/App.vue)。
