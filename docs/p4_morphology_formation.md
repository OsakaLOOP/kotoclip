# P4 完善：活用链与整体构词

日期：2026-09-22。本文定义本轮实现契约；完成状态和十段实际输出另记验收结果。

## 目标与范围

P4 生成可供后续查询和语法解释直接引用的活用链、形态 occurrence、整体构词与查询形式。UniDic、GiNZA、KWJA 的原始对象保持各自身份。模块归并共同正文上的证据，输出成员、连接理由、所有权及待定原因。

P4 的核心验收范围从 token 到语法活用链和整体构词，保证成员及范围、连接关系、规范基本形式、occurrence 和查询对象。GiNZA 正式 token 是整体构词的主要来源；依存、文节及 KWJA 句法标签作为实验性辅助证据保存。依存提出的多 token 整体保持 candidate，来源关系可追溯性单独记录。

本轮完成现代日语常用活用体系、补助用言连接与主要缩约形式，并保留 P01、P02 的文语连接。现代日语的构式、惯用表达及语境义项由后续语法模块消费这些对象。词典记录绑定和阅读分组沿用后续阶段的职责。

开发采用 `no-stop-gpt / Prevent`：复用现有来源协议和字符对齐，使用领域内的有限状态与显式连接表，避免增加通用规则运行器。状态机及来源关联集中在 NLP 层，词典 I/O 由 core 查询服务负责。

已阅读 P01、P02、P03 的现有 Markdown 记录。P01 有 `成立した`、`発展せしめる`，GiNZA 将后者分成两个文节；P02 有 `霽れて`、`欝すれども` 及词法分析不稳定的 `送梅`、`流る`；P03 有 `ふけっていようと`、`吹聴していようと`、`頓着しない`，可检查补助用言、意志形和否定。P01 的文节划分表明：文节边界应作为结构证据，明确的形态连接具有独立成立条件。

当前适配器的 `compound` 来自正式 C 模式 token 带有多成分的 A 模式诊断信息；它通常只引用一个正式 token。多正式 token 的整体关系须另外读取 dependency。`sub_tokens` 保留来源诊断用途，统一成员始终引用 UniDic token。

## 来源协作与判定顺序

| 信息 | 使用方式 |
| --- | --- |
| UniDic `pos1..4/cType/cForm` | 识别词类、连接形和功能成分，确定具体形态转移条件 |
| UniDic `orthBase/kanaBase/lemma/lForm` | 生成相互配对的核心查询表记和读音 |
| UniDic 首尾变化及结合字段 | 保留词内部变化证据；按字段自身含义使用，不直接等同于句法接续许可 |
| GiNZA 正式 token 及 `tag/morph` | 识别跨 UniDic 成员的一个词、补充活用身份，发现两来源词法分歧 |
| GiNZA `aux/cop` 依存 | 确认辅助或系词关系，参与功能所有权和跨 token 连接判断 |
| GiNZA `compound` 依存 | 建立词汇核心内部关系，供整体构词和复合核心引用 |
| GiNZA 文节、主辞、`bunsetu_position` | 辅助判定补助用言归属；显式记录跨文节连接 |
| GiNZA 句界和依存目标 | 限定候选作用域，识别连接到其他谓词的结构冲突 |
| KWJA 基本句、谓语及标签 | 为已形成的 occurrence 添加上下文引用和形式解释线索 |

判定依次检查共同正文身份、字符连续性、词法连接条件、来源结构支持或冲突。GiNZA 正式 token 与 UniDic 词界通过现有多对多覆盖关联；部分覆盖保存精确交集及诊断。

GiNZA 必须实际影响结果：同一正式谓词 token 可支持多个 UniDic 成员构成复合核心；明确的 `aux/cop` 关系可支持功能身份；补助用言的关系和主辞决定父链候选。每次采用均保存来源节点或关系 ID。来源一致、结构缺失和来源冲突分别可见。

词法许可明确、GiNZA 结构有分歧时保留形态结果和冲突证据，例如 P01 的 `発展せしめる`。词法许可不足、只有模型辅助关系时产生候选连接。模型的 `aux` 标签本身无法许可任意词形相接。标点、换行、空白和正文不连续是本轮链的硬边界。

## 活用状态机

### 状态与输入

状态包含 `category`（动词、形容词、形状词、名词谓语、助动成分）、`form`（未然、连用、终止、连体、假定、命令、意志、词干、接续形）、`last_morpheme` 与已构成的成员范围。`cType/cForm` 原值随成员保留；状态枚举承担连接条件，避免通过解释字符串传递状态。

语义操作单独表达为使役、语态候选、否定、过去、敬体、愿望、推量、条件、命令、禁止、接续和补助用言连接。否定与过去等操作按实际成员顺序记录。状态转移依据前项连接形和后项身份，不采用一条固定的语义槽位顺序；`ませんでした` 等复合形式可按局部许可连续处理。

### 主要转移

| 前项条件 | 后项身份 | 转移与输出 |
| --- | --- | --- |
| サ変可能名词 | サ行变格 `する／為る` | 扩展词汇核心，保留名词和动词成员，生成 `名词＋する` 基本形 |
| 未然形 | `せる／させる／しめる` | 使役；输出状态取助动成分实际活用形 |
| 未然形 | `れる／られる` | 语态形式；保存受身、可能、尊敬、自发候选 |
| 未然形或形容词适配连接 | `ない／ぬ／ず／ん` | 否定；敬体否定按 `ます` 的未然连接处理 |
| 连用形及音便 | `た／だ`（过去助动词） | 过去；`だ` 根据词性与活用型区别于系词 |
| 连用形 | `ます／たい／たがる` | 敬体、愿望或愿望表现；`たがる` 依实际词性保留成分身份 |
| 名词、形状词或相容终结形式 | `だ／です`（系词、敬体） | 判断或敬体；名词核心可形成谓语链 |
| 连用形及音便 | 接续助词 `て／で` | 接续形；助词范围属于前项链 |
| 假定形 | 接续助词 `ば` | 条件接续；保存假定形及助词的各自范围 |
| 终止形 | 终助词 `な` | 禁止 occurrence；须区别名词修饰的 `な` |
| 实际命令、意志形 | 当前词元 | 生成命令、意志 occurrence，覆盖单 token 活用 |
| `て／で` 接续形 | `いる／ある／おく／しまう／いく／くる／みる／くださる／もらう／あげる` 等补助用言候选 | 开始功能链，引用前项链和接续 operator；利用 GiNZA 关系与文节主辞检查所有权 |
| 连用形或已识别接续 | `てる／でる／ちゃう／じゃう／とく／どく` 等缩约身份 | 原始 token 作为一个成员，保存展开形式与缩约类型，不虚构来源 token |

补助用言许可同时检查 UniDic 的非自立身份或 GiNZA 的功能关系、词元身份和前项接续。`そこにいる` 的 `いる` 为独立谓词；`読んでいる` 的 `いる` 可形成关联功能链。`てある` 等同形结构保留体貌与独立用法的候选，语境解释由后续层决定。

现代活用类别覆盖五段、一段、カ变、サ变、形容词和形状词／系词。实际音便、连用形和未然形直接利用来源字段。P01、P02 的文语变体采用明确的附加连接条件，来源无法支持的片段保存待定理由。

### 链与 occurrence 契约

| 对象 | 必需信息 |
| --- | --- |
| `MorphologyChain` | 局部 ID、核心成员、全部成员、范围、词汇／功能角色、父链与连接 operator、出现形、显示形、基本形、词元形、查询形式、最终状态、证据和状态 |
| `MorphologyOperator` | 类型、规则身份、输入和输出状态、实际成员与范围、候选解释、来源引用 |
| `MorphologyOccurrence` | occurrence ID、形式身份、链及 operator 引用、精确命中范围、上下文整体范围、候选解释和识别状态 |
| `SourceEvidence` | provider、节点或关系 ID、实际使用的字段和用途 |
| 诊断 | 受影响范围、连接两端、原因、冲突来源引用 |

operator 表达处理过程，occurrence 表达正文中可引用的形式出现。同一形式由同一组成员和 operator 唯一定位，避免再次扫描助动词生成重复实例。受身等多义形式可以具有确定的形式身份和待定的语义候选；二者分别记录。

`読んでくださった` 产生 `読んで → 読む` 词汇链、`くださった → くださる` 功能链和明确的父链连接。过去 operator 归功能链。`専有してしまっている` 有词汇链及两级功能链，依次保存父链关系。`静かな` 的词汇查询形为 `静か`，显示原型为 `静かだ`。

缩约的 `normalized_form` 和显示原型采用规范基本形式 `ている／てしまう／ておく`；补助动词查询形采用 `いる／しまう／おく`。`てる／でる`、`ちゃう／じゃう`、`とく／どく` 分别归入同一规范形式。原始表面串、词元字段及连接 operator 保存实际缩略、浊化和活用，例如 `読んじゃった` 保留 `じゃっ` 与过去成员，规范形式为 `てしまう`，查询形为 `しまう`。

## 整体构词

### 候选生成

构词处理三个可追溯来源：GiNZA 正式 token 覆盖多个 UniDic 成员、显式 compound 节点、正式 token 之间的 `compound` 依存。相同范围和成员合并来源证据。单正式 token 与单 UniDic token 同范围时保留整体身份，并与原子查询目标建立等价关系。

依存构词从主辞向其 `compound` 子项收集成员，仅采用连续且完整覆盖的成分集合。成员间出现助词、标点或覆盖缺口时保留待定候选与具体原因。文节、实体名和 `nmod` 修饰关系可提供上下文证据；单独的这些范围不足以确认词汇整体。

### 核心与活用协作

构词与活用通过核心成员相接。先取得 GiNZA 的正式词汇核心范围，再进行活用连接；整体词输出同时保留核心范围及其关联链。活用后的查询形使用核心内部已出现的非末端成分，加末端词头的基本形，例如复合动词的还原由实际词头字段支持。サ变核心保存名词查询形与 `する` 形式。功能助动成分留在链对象中，整体词查询使用词汇核心。

GiNZA 正式 token 内同时出现词汇成分和活用成分时，先根据 UniDic 的身份和状态转移确认核心。模型词界与核心成员冲突进入待定状态，保留两套范围用于复核。

### 整体对象与查询形式

每个 `FormationNode` 保存稳定局部 ID、核心范围、UniDic 成员及内部查询引用、词头成员、输出词性、正式来源 token、构词关系、关联活用链、出现表记与候选查询形式。沿用现有 formation 对象承载整体构词，避免相同信息分别维护在两套整体对象中。

来源观察与应用状态分别记录：来源引用说明模型实际输出，整体构词采用 `observed/candidate/pending`，活用链采用 `resolved/candidate/pending`。核心链存在分歧时，整体状态传播为 candidate。词典验证独立为 `not_checked/matched/no_match`；查询错误沿现有请求错误协议返回。P4 分析输出 `not_checked`，词典查询入口按目标执行验证，整体没有词条时仍可查询内部成员。

每个查询形式包含 `form/reading/reading_field/evidence`。出现表记使用出现假名；基本表记使用基本假名；词元表记使用词元读法。多个成员的假名拼接注明 `composed`，属于查询证据，整体读音可在词典验证中进一步确认。任何成员缺少读音时整体读音为空。GiNZA 的读音与规范词形可保存为独立候选及来源引用。

同范围合并证据，包含关系保留整体与成分，交叉范围保存竞争引用。P4 提供完整候选结构，后续查询与阅读层依据词典记录和上下文选择展示目标。

## 接入与生命周期

实现协议为 `morphology-artifact.v3`、`formation-artifact.v2`、`dictionary-candidates.v2` 和 `unified-document.v8`。`FormationNode.word` 承载整体词详情，`morphology.occurrences` 承载形态出现。`QueryCandidate` 响应携带目标引用与 `matched/no_match` 词典状态。来源缺失可通过现有 `external_sources` 和 provider 状态查询，形态状态独立描述当前证据下的识别结果。

统一入口在来源覆盖校验后建立 GiNZA 词汇核心，再计算活用链和整体查询对象。仅 UniDic 的首批结果标记来源尚未齐备；GiNZA 追加后重建受其影响的链、构词和查询候选，随会话现有版本更新一次提交。

完整来源入口、SyntaxArtifact 导入入口和 native 入口采用相同派生流程。仅含跨度的 SyntaxArtifact 可生成范围证据，依存辅助能力标记缺失。算法版本进入缓存键；Rust 与 TypeScript 同步字段和序列化契约。局部 ID 在同一输入及算法版本下稳定，外部引用携带文档和产物版本。
