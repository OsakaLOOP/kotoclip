# P4 十段来源输出审计（开发基线）

日期：2026-09-22

本文保存本轮开发前的异常归因及设计依据。当前实现契约以 [P4 活用链与整体构词](p4_morphology_formation.md)为准，完成状态和最新十段结果见 [P4 样本输出复核](p4_sample_review.md)。活用链与 GiNZA 来源支持的整体构词已纳入同一 P4 阶段；下文的旧输出数量及后续清理建议保留为基线记录。

审计对象是 `data/validation/refractor_source.txt` 的 p01-p10、`experiments/p4-sample-review/p01.json` 至 `p10.json` 保存的来源结果，以及 `data/validation/p01-p4-integration.md` 至 `p10-p4-integration.md` 的脚本摘要。

## 范围定义

P4 在本轮审计中包含正文准备、语域路由、UniDic、GiNZA、KWJA、来源坐标对齐、来源结构统一，以及不改变来源语义的主要提取与聚合能力。P4 的对象必须同时能够被内部分析模块引用，并通过稳定 schema、查询入口或来源查看接口供外部模块消费。

P4 包含下列对象：

- 正文、语域路由、UniDic 原子词元、字段和查询形；
- 活用链、operator、连接关系等来源字段驱动的形态聚合；
- GiNZA 正式 token、compound、文节，KWJA 基本句、谓语、论元和篇章关系；
- 多来源字符对齐、结构实体、关系、选择候选和诊断；
- 由原子词元与已确认来源 compound 生成的来源级词典查询目标；
- 内部 Rust API、CLI/IPC 和外部结构查看接口对上述对象的读取能力。

P4 之后、不计入 P4 完成度的对象是：应用生成的构词候选、最长范围选择、词汇竞争决定；语法概念、sense 选择、表达成立判断；阅读单位、解释内容、颜色、高亮和其他用户可见投影。

用户可见形式与具体判断逻辑分别属于后置层。P4 提供证据对象和消费接口，后置层决定如何组织、排序、确认或拒绝这些对象。

## 总体结论

P4 已取得可供内外部消费的来源证据与统一对象。十段共 980 个字符、634 个 UniDic 词元；GiNZA 和 KWJA 均实际执行，字符覆盖能够映射回共同正文。UniDic 适合作为词形、词元、读音和词典查询的主来源；GiNZA 的正式 token、compound、文节和依存结果整体稳定；KWJA 的基本句、谓语、论元、节功能和篇章关系具有补充价值。活用链、来源 compound 聚合、结构图和来源级查询目标可以作为 P4 产物继续被内部与外部调用。

来源质量存在清楚的边界。UniDic 对文语旧字和未知词会缺少词元或读音；GiNZA 的 compound 只覆盖模型明确提出的少量整体词；KWJA tiny 模型的词界、词元和读音存在明显错误。统一层已经保留原始来源与对齐关系，后续模块应按来源职责取用，避免采用 KWJA 的词汇身份和读音。

脚本摘要混入了 P4 之后的派生结果，造成“外部模型切错词”“P4 已完成语法识别”“阅读单位已经可用”等错觉。异常范围主要来自旧通用扫描和阅读单位选择，原始三来源没有输出 `うち大正`、`ところ暑く`、`午後4` 等整体。P4 需要保留来源级 token/compound 的消费能力，但不应把后置判断结果伪装成来源聚合。

## 1. 正文准备与语域

十段正文均保留原字符范围，来源结果使用 Unicode scalar 半开区间。p01-p05、p07-p10 选择 CWJ；p06 含新闻引语，文档级 `selected` 为空，由 routing runs 保存分段选择。该行为符合分单元语域路由的设计。

本组样本没有 ruby 删除或复杂规范化造成的坐标损失。GiNZA、KWJA 的标准化结果均能映射回正文。P4 后续仍需保留 `source_text`、规范化映射和删除范围，因为当前十段无法覆盖组合字符、控制字符和作者注音的全部情况。

## 2. UniDic 词元

### 可用内容

UniDic 的 29 列字段完整保留，`pos1-pos4`、`cType`、`cForm`、`lemma`、`orthBase`、`kana`、`kanaBase`、词首词尾变化和词元 ID 均可追溯。出现形、基本形、词元形和对应读音能够分开使用。

代表性结果准确：

- p01 `発展／せ／しめる` 保留サ变词干、使役助动成分和文语形式；
- p03 `ふけっ／て／いよう／と` 保留动词连用形、接续助词、补助用言意志形和接续助词；
- p04 `掲載／さ／れ／た`、`支払わ／なけれ／ば／なら／ない` 的各成员和活用形齐全；
- p05 `扱わ／れ／ます` 保留未然形、`れる` 和敬体助动词；
- p09 `覗か／れ／てる` 保留受身候选与口语缩约的原始成员；
- p10 `専有／し／て／しまっ／て／いる` 保留两层补助用言组合所需的全部词元。

助词和助动词单独成为短单位词是正常的 UniDic 结果。`教科用の図書` 的来源词元是 `教科／用／の／図書`，`の` 为格助词；`鏡の裏` 同样是 `鏡／の／裏`。P4 应保存这些原子边界，并通过统一对象和查询接口提供给后置结构层；文节、短语或用户展示范围由后置层决定。

### 来源限制

p02 的旧字和文语暴露了词典覆盖边界：`雜`、`搖` 为 unknown，缺少词元和读音；`欝` 能还原为 `鬱`；`蕩` 被分析为文语动词 `蕩ける`；末尾 `流る` 的 `流` 被识别为名词。此类结果需要保留原始表面串和 unknown 状态，后续可用旧字规范化、词典记录和上下文提出修正候选。

`れる／られる` 的来源词元天然允许受身、可能、尊敬、自发等解释。P4 提供形式身份和候选集合。当前摘要中的 `passive_potential` 来自 `morphology.rs` 对 lemma 的统一派生，并明确保存四类候选；它不是 UniDic 已经判定“受身兼可能”。p04 `掲載された`、p05 `扱われます`、p09 `覗かれてる` 的语境均优先支持受身，义项选择属于后置语法能力。

## 3. GiNZA 来源

### 正式 token 与 compound

GiNZA 的应用输入采用 Sudachi C 模式正式 token。十段共提供 20 个 compound：

- p01：`一転機`、`総同盟`、`方向転換`；
- p03：`哲学者`；
- p04：两处 `教科用図書`、两处 `著作物`、`文化庁`、`著作権`；
- p06：`神戸市`、`会社員`；
- p07：`気象庁`、两处 `線状降水帯`、`静岡県`；
- p08：`大多数`、`無意識`；
- p09：`見渡す`；
- p10：`這い上がる`。

p02、p05 没有 compound。该结果表示 GiNZA 没有提出整体范围，并不表示正文不存在复合词或专名。`青空文庫`、`雲霧昂騰` 等范围需要后续词典或构词模块处理。

GiNZA 的 `sub_tokens` 是 tokenizer 的 A/B 模式诊断信息。`見渡す` 的 `見／渡す`、`這い上がる` 的 `這い／上がる`、`線状降水帯` 的多种内部拆分均不应新增正文词元。当前 P4 保存正式 token 和诊断信息的方式正确。

### 文节和依存

GiNZA 文节边界总体适合结构查看。例如 p09 给出 `見渡すが、`、`鏡の`、`裏から`、`覗かれてるとは`；p10 将 `専有してしまっているという` 保持在同一文节。依存标签提供 `nsubj`、`obj`、`obl`、`acl`、`advcl` 等结构证据。

compound 和文节具有不同职责。`教科用の図書` 中的 `の` 属于文节内部功能成分，GiNZA 没有把带 `の` 的整个短语声明为复合词；`当該教科用図書` 中的 compound 范围是 `教科用図書`，修饰语 `当該` 位于范围外。两种处理都符合原句结构。

## 4. KWJA 来源

### 可利用的结构证据

KWJA 的基本句、谓语、论元和节标签可以补充 GiNZA。代表结果包括 p03 的意志与逆条件线索、p05 的敬体线索、p09 的 `見渡すが` 逆接篇章关系、p10 的长定语节及谓语关系。基本句和小句应保持各自身份，并通过结构图和统一引用供后续语法识别消费。

### 词法错误

KWJA tiny 模型不适合作为词汇身份和读音来源。p09 的原始结果包含下列错误：

- `見渡す` 的读音预测为 `みつす`，正确读音是 `みわたす`；
- `鏡` 的读音预测为 `あし`，正确读音是 `かがみ`；
- `気づか` 的 lemma 预测为 `気づかる`，应还原为 `気付く／気づく`；
- `鏡の裏` 中的 `の` 标为接续助词，句中功能是名词修饰关系的格助词；
- `覗かれてる` 被切成 `覗か／れて／る`，未正确表达 `覗か／れ／てる` 的口语缩约结构。

KWJA 的上述错误不会污染 UniDic 词元，因为统一结果保留两套来源空间。后续模块应使用 KWJA 的基本句、谓语、论元和篇章标签，同时通过字符覆盖关联 UniDic 成员。

## 5. 对齐与统一结构

十段的对齐组均报告 `status=complete` 和 `reason=equal_coverage`。该状态只表示来源范围能够完整覆盖共同正文。它不评价 lemma、读音、词性、主辞或依存关系的语言学正确性。

`1:n`、`n:1` 和 `n:m` 是来源词界差异的正常表示。例如 p09 `見渡す`、`覗かれてる` 在 UniDic、GiNZA、KWJA 中采用不同粒度，对齐层以共同字符范围保存成员关系。当前机制适合后续按职责选择来源。

结构图同时保存 GiNZA 和 KWJA 实体、关系和默认选择。报告中的 `incomplete` 表示部分结构实体无法形成完整的统一引用；它与 token alignment 的 `complete` 属于不同指标。摘要应分别展示覆盖完整性、结构引用完整性和来源诊断，避免用一个 `complete` 概括全部质量。

## 7. 摘要报告的越界内容

`export_p4_sample_report.py` 在同一份报告中输出 P4 来源与多个后置层，容易混淆归因。各栏目应按下表解释：

| 栏目 | 实际来源 | P4 判断 |
| --- | --- | --- |
| `词语` | UniDic token 的筛选摘要 | 属于 P4，但脚本主动省略助词、助动词和标点，不能代表完整 token 序列 |
| `构词` 中 `compound;observed` | GiNZA compound 映射 | 属于 P4 来源证据 |
| `文节`、`来源关联`、`对齐` | GiNZA/KWJA 与统一层 | 属于 P4 |
| `小句` 中 provider 结果 | GiNZA/KWJA | 属于 P4；`local;candidate` 是内部派生，排除 |
| `活用` | 内部 morphology chain | P4 提取对象；最终组合解释属于后置层 |
| `构词` 中各类 `candidate` | 应用构词扫描 | P4 之后，且当前实现应移除 |
| `语法`、`表达` | 功能语素提取与规则扫描 | 原子功能身份可作为 P4 候选；构式和义项属于后置层 |
| `词汇决定` | 词典绑定与候选竞争 | 来源级 token/compound 查询可纳入 P4；最长范围和竞争决定属于后置层 |
| `阅读单位`、`解释`、`投影` | 用户可见组织 | P4 之后，设计待定 |

脚本的 `词语` 栏过滤 `助詞`、`助動詞`、`記号`、`補助記号`，因此 `の` 不会出现在该栏。`阅读单位` 又会显示单独的 `の`，因为后置实现对没有词汇候选覆盖的 morpheme 建立单成员单位。这一现象来自报告筛选与阅读单位 fallback，来源分析没有丢失或错误插入 `の`。P4 对外消费应提供完整 token 和 query target，不能只提供筛选后的词语摘要。

## 8. 异常范围的准确归因

### `うち大正`、`大正十`、`労働運動`

原始 P4 中，p01 的 GiNZA compound 只有 `一転機`、`総同盟`、`方向転換`。`うち大正`、`大正十`、`十四`、`四年`、`労働運動`、`政治運動` 和 `日本労働` 均由后置的 `numeric_counter` 扫描产生。

原规则要求“数词 + 助数词”。`language_rules.rs` 的 UniDic 适配删除了第一项的 `数` 子词性约束，也删除了第二项的 `接尾` 子词性约束；第二项同时保留 `名詞` 并追加 `接尾辞`。实际条件退化为“任意名词 + 任意名词或接尾辞”。p01 的 `うち` 是名词，`大正` 是固有名词，两者因此误命中。

阅读单位实现从同一起点的候选中选择成员数最多者，并在词典绑定之前执行，不检查 candidate 状态或词典记录。它先选择 `うち大正` 并消费 `大正`，随后选择 `十四`，最终显示为 `その | うち大正 | 十四 | 年`。完整错误链是“约束丢失 → 错误构词候选 → 未验证候选进入阅读单位”。

### `ところ暑く`

p02 的 GiNZA 没有输出 compound。`ところ暑く` 来自后置 `derived_adjective` 扫描。原规则要求“名词 + 形容词性接尾成分”；适配删除 `接尾` 子词性约束，并让第二项接受 `形容詞` 或 `接尾辞`。普通形容词 `暑く` 因而错误命中。该范围与外部来源无关。

### `教科用 | の | 図書` 与 `当該教科 | 用 | 図書`

两处现象需要分别判断。

`複製する教科用の図書` 的原文确有 `の`。UniDic 的 `教科／用／の／図書` 和 `の=格助詞` 正确；GiNZA 没有把整个短语当作 compound。摘要中的 `教科用 | の | 図書` 来自后置候选 `教科用` 与单 token fallback。它可以作为一种界面分组方案，但阅读单位设计尚未确定，P4 不作合格判断。

`当該教科用図書` 的原文没有 `の`。GiNZA 正确输出 `教科用図書` compound。后置扫描同时产生错误候选 `当該教科`。阅读单位从 `当該` 开始选择 `当該教科` 并消费 `教科`，随后已经无法采用从 `教科` 开始的 `教科用図書`，最终显示为 `当該教科 | 用 | 図書`。外部 compound 正确，后置重叠选择破坏了它。

### `20 | 日 | 午後4 | 時過ぎ`

p07 的 GiNZA compound 只有 `気象庁`、两处 `線状降水帯` 和 `静岡県`。时间范围全部来自后置扫描。退化后的 `numeric_counter` 把相邻名词组成 `20`、`午後4`、`4時`；退化后的 `derived_adjective` 把名词与接尾辞组成 `0日`、`時過ぎ`。重叠候选再由“同起点成员最多”决定，得到不稳定的时间切分。

UniDic 原始词元为 `2／0／日／午後／4／時／過ぎ`，词性分别保留数词、助数词和时间名词信息。P4 证据足以支持后续专门的数词与时间表达模块，当前扫描结果没有利用这些完整约束。

### `東京市 | 内 | 電車`

p08 的 GiNZA compound 只有 `大多数`、`無意識`。`東京市`、`市内`、两处 `満員電車` 和 `満員混雑` 均为后置扫描结果。`東京市` 与 `満員電車` 仍由退化的 `numeric_counter` 产生，名称标签与实际构词类型完全不符。

阅读单位先采用从 `東京` 开始的 `東京市`，消费 `市`；从 `市` 开始的 `市内` 随即失效，结果成为 `東京市 | 内 | 電車`。该输出无法说明 `東京市` 是否是上下文中的正确词汇整体，只能说明重叠候选选择采用了起点优先。

### 重复的 `の`、`た`、`て`

语法栏目中每个 `の`、`た`、`て` 都可能同时出现功能语素候选、形态特征和目录规则结果。来源层只提供对应 UniDic token 和 KWJA/GiNZA 结构；重复 occurrence 由后置模块分别建立后再合并展示。P4 不应统计这些 occurrence，也不应由数量推断语法覆盖率。

## 9. P4 后续边界

P4 输出应包含可追溯的来源证据、统一引用和主要提取/聚合对象。建议重新生成一份 P4 报告，包含完整 UniDic token、活用链、两套 provider 实体与关系、GiNZA observed compound、来源小句、对齐组、结构选择、来源级 query target 和诊断；应用构词 candidate、最长范围竞争、语法/表达成立判断、阅读单位、解释和投影移到单独后置报告。

语法规则和表达识别作为 P4 后的独立阶段保留设计位置，当前开发跳过。该阶段未来消费 UniDic 形态、GiNZA/KWJA 结构和词典身份，输出候选、义项与成立依据。

阅读单位位于词汇、语法和表达决定之后。其边界、整体与成分入口、功能语素归属和重叠选择尚需单独设计；P4 只提供它所需的 token、chain、compound、structure 和 query target，不生成用户可见阅读单位。

## 11. 词典范围能力附录

### p02 整体词汇记录

`送梅` 是季语整体词，读作 `そうばい`；完整词形 `送り梅雨` 读作 `おくりばいう`。GiNZA 与 KWJA 当前均未输出 compound，UniDic 又将 `送`、`梅` 分开，因此来源构词层为空属于 provider 能力边界。该词应进入后置整体词汇层，保存正文范围、整体表记、短读音 `そうばい`、完整词形 `送り梅雨`、完整读音 `おくりばいう`、季语标签及人工或词典来源。整体词汇层的确认结果可以生成 dictionary candidate，不能回写为 provider observed compound。

### 旧字形前置计划

在 UniDic、GiNZA、KWJA 之前增加 `kyukanji.js` 类旧字形归一化模块。模块输入原文，输出规范化正文、规范化字符到原文字符的半开区间映射和删除范围；UniDic 使用规范化正文分析，统一层仍以原文坐标保存 `surface`，查询层同时保留原文表记与规范表记。`雜`、`搖`、`霽` 等字形由该映射进入 `雑`、`揺`、`霽` 或词典指定的规范查询形，原文显示继续使用正文字符。

### 性能处理顺序

基础 P4 分析已经移除同步规则扫描和词典绑定，词典改为实际查询时懒加载；该路径消除首次分析中约 50 秒的后置处理。GiNZA 与 KWJA 请求已经并行提交，结果缓存和常驻 worker 继续复用；KWJA tiny 模型只加载 `char`、`word` 模块，并按 CPU 核数设置线程上限。来源分析主要受两者中耗时较长的一项约束，后续仅保留低于 1 秒收益的细节优化。

最长范围判断位于 P4 之后；P4 仍应提供原子 token、来源 compound、词形/读音 query form 和可被词典引擎读取的来源级查询目标。本节沿用十段输出追查现状，不将后置范围选择计入 P4 评价。

当前 `collect_dictionary_candidates` 已为单个 UniDic token 和已有来源 formation 建立查询目标，能够供内部绑定逻辑和外部候选查询接口读取。系统没有从点击位置向左右枚举连续 token，也没有用词典反向发现最长有效词条；这些属于后置范围判断。`bind_lexical` 可以用整体表记和拼接读音验证既有范围；查询引擎可以处理精确表记、别名、规范表记、读音和词性排序。

十段的后置输出共有 80 个词汇范围决定：31 个 `observed`、47 个 `candidate`、2 个 `pending`。formation 层另有 80 个节点，其中 20 个是 GiNZA observed compound，60 个是后置扫描 candidate。两组统计经过范围合并和词典绑定后不再一一对应，不能用 observed 比例评价 provider 或最长词能力。

以来源范围为起点时，词典验证能够处理 `教科用図書`、`著作物`、`会社員`、`気象庁`、`線状降水帯`、`大多数`、`無意識`、`見渡す`、`這い上がる` 等整体。`神戸市` 有正确的 GiNZA 范围，但本地词典没有整体记录，状态保持 candidate；这属于词典覆盖不足。p09、p10 的复合动词在 GiNZA 已经是单个正式 token，整体查询不需要再次扩大范围。

最长范围选择目前不可用。阅读单位在 `bind_lexical` 之前生成，按成员数量选择候选，不检查来源、状态、词典绑定或重叠优先级。前端点击只提交 token ID；后端虽有 `QueryCandidate`，当前界面没有使用 candidate ID 或 reading unit 的 `query_target_ids`。用户实际获得的是单 token 查询，整体候选尚未接入桌面交互。

后续词汇模块可以依赖 P4 的连续 token、GiNZA compound 和结构边界，从点击位置枚举合理范围，再以整体词条、拼接读音、词性兼容和上下文验证候选。只有完成竞争决定的范围进入阅读单位；内部 token 保留独立查询入口。
