# P4 十段输出逐层审计

日期：2026-09-21

对象是 `data/validation/refractor_source.txt` 的 p01-p10，以及脚本生成的 `data/validation/p*-p4-integration.md`。本报告只根据实际输出、日语语法和当前设计协议判断，不运行测试。

## 总结结论

P4 已经形成完整的“来源分析 → 统一对象 → 应用层 → 投影”数据路径。十段的字符范围、来源 token 覆盖和对齐分组均有可追溯结果，UniDic 对词形、词元、读音和活用的原子证据总体可信。应用层仍处于“候选收集和局部规则命中”阶段：构词竞争没有完成选择，功能语素大多停留在单点标签，语法构式只覆盖少数目录规则，表达识别几乎为空，阅读单位把不少尚未确认的候选直接组织成了用户可见单位。

按设计目标分级：L0/L1 可作为分析证据使用；形态层达到“可复核”，未达到“完整活用链”；构词和词汇层达到“候选生成”，未达到“稳定词汇整体”；语法层达到“局部规则可用”，未达到“语义义项和组合解释”；表达层未接入完整匹配；投影层能定位已有 occurrence，但会忠实投影未决候选，因而不能直接视为最终教学输出。

## 1. 字符范围、来源和对齐

### 实际结果

十段均报告 `status=complete`，`reason=equal_coverage`。对齐组数量随篇幅从 p09 的 41 组到 p04 的 288 组，绝大多数为 `1:1`；p01、p02、p03、p06、p07、p09、p10 出现 `1:n`、`n:1` 或 `n:m`，报告保留了交叠关系。GiNZA、KWJA 都实际返回了 token、文节、句法关系和谓语信息。

### 日语和设计判断

作为来源证据，这一层准确。`見渡す`、`這い上がる`、`方向転換`、`線状降水帯` 的外部复合跨度被映射到正式 UniDic token；p09 的 `覗かれてる` 出现来源内部边界差异，也被保留为多对多对齐。设计要求“来源观察与应用决定分开”，当前对齐层符合要求。

“complete”只说明字符覆盖完成，不说明语言分析正确。p09 的 KWJA 小句不完整、p01-p10 多处 GiNZA 与本地小句范围不一致，仍被统计为完整对齐；报告需要同时暴露结构完整性和覆盖完整性，避免把 `complete` 误读为句法正确。

### 典型缺口

`見渡す` 在 GiNZA 的 A/B 子切分与正式 C 模式 token 不同，当前保留诊断是正确的；应用层必须继续只使用正式 token。p09 的 `覗かれてる` 同时涉及 `覗く + れる + ている` 和口语缩约，来源范围可用，后续组合仍需规则确认。

## 2. 词元和活用

### 实际结果

十段共 634 个 UniDic token、约 500 条活用链。输出能给出词性、出现形、词元、读音和部分活用标签。代表形式均被拆出：p01 `発展／せ／しめる`、p03 `ふけって／いよう／と`、p04 `支払わ／なけれ／ば／なら／ない`、p05 `扱わ／れ／ます`、p08 `選んで／乗って／いる`、p09 `覗か／れ／てる`、p10 `専有／し／て／しまっ／て／いる`。

### 日语和设计判断

原子形态判断大体准确，尤其是 `発展せしめる` 的使役、`支払わなければならない` 的否定条件和义务成员、`読んでくださった` 类补助用言链所需的成员边界都已存在。p02 的文语材料中 `すれども`、`霽れて`、`よりて` 也保留了可供解释的词形证据。

当前实现仍偏向“每个词元一条链”。设计要求的 chain/operator/parent ownership 尚未完整落地：输出中的 `grammar.functional.iru`、`grammar.functional.shimau` 和 `morphology.form.te` 经常是相互独立的 occurrence，尚未统一成为“词汇核心 → 连接形 → 补助用言 → 时体”的有序链。`発展せしめる`、`専有してしまっている`、`覗かれてる` 因此只能看到成员，尚不能稳定生成完整解释。

### 典型错误或不足

- p04 `掲載された` 被标成 `passive_potential+past`。`掲載された` 在该法律条文中是受身过去（“被刊载的作品”），不是可能态。UniDic 的形态字段允许这两种候选，但应用层必须用主语/修饰关系和词典规则消歧。
- p05 `扱われます` 被标成 `passive_potential+politeness_masu`。句子“作品は…扱われます”是受身敬体，不能把可能态作为同等最终解释。
- p09 `覗かれてる` 的 `れ` 被标成 `passive_potential`，日语上应优先解释为受身；`てる` 是 `ている` 的口语缩约，当前规则命中正确，但需要把缩约归入同一补助用言链。
- p08 `いえ` 的词元是 `言う`，在 `とはいえ` 中属于固定让步构式成员，不能仅按普通动词“说”展示。

## 3. 构词和词汇整体

### 实际结果

十段共 61 个 formation 节点，其中 p01、p04、p07 有大量冲突，p08 有 1 个冲突。明确观察到的整体包括 p01 `方向転換`、p03 `見た` 相关结构、p06 `神戸市`、p08 `大多数`、`無意識`、p09 `見渡す`、p10 `這い上がる`。词汇决定层的 `observed` 数量很少，p02、p04、p07 主要是 `candidate` 或 `pending`。

### 日语和设计判断

来源复合词映射本身可用，且没有把 GiNZA A/B 子 token错误提升为正文词元，符合设计。词汇整体确认严重不足，无法支撑“阅读胶囊、整体查词、整体读音”的目标。

### 典型错误或不足

- p04 的法律术语 `教科用図書` 多次出现，阅读单位却出现 `教科用 | の | 図書`、`当該教科 | 用 | 図書` 等切分。这里的 `用` 是复合词内部接尾成分，不能在没有结构决定的情况下被当作格助词 `の` 前后的独立阅读单位。
- p07 `線状降水帯` 已有 GiNZA compound，但词汇决定仍以 17 个候选为主，`線状降水帯` 没有稳定 observed 绑定；气象新闻中的核心术语因而不能作为整体查询对象。
- p06 `神戸市` 的整体被保留，说明同类实体可以完成；p04/p07 的竞争消解策略尚未达到同一稳定性。
- p02 `雲霧昂騰`、`ところ暑く` 被列为 candidate。前者是文语汉语词整体候选，后者是 `ところ` 名词性形式加形容词连用形的句法组合，不能仅凭相邻字符作为词汇整体。
- 旧字形和未知词的原子保留较好：p02 的 `雜`、`霽れ`、p03 的 `すね`、p10 的 `ゾワゾワゾワ` 没有被强行替换；词典候选需要同时标明“正文可读、词典未确认”。

## 4. 文节、小句和来源结构

### 实际结果

GiNZA 文节在十段均有输出，数量随文本长度合理；KWJA 提供基本句、谓语和论元关系。小句同时有 `local;candidate` 与 provider 结果，p01-p10 多数段落存在两侧边界差异。p09、p10 的 `incomplete` 分别为 6、5，p08 为 0。

### 日语和设计判断

文节层适合做结构证据。p08 的 `たとえ無意識とはいえ` 被独立识别，p09 的 `見渡すが` 与后件 `気づかない` 的逆接关系可见，p10 的长定语节 `…専有してしまっているという後ろめたさ` 也得到整体范围，说明依存和文节数据具有解释价值。

本地小句生成仍是粗粒度候选，不能与 KWJA 小句等同。p09 的本地小句把前半句和后半句拆成两个候选，但 KWJA 只稳定给出前项；p10 的长定语节和主句关系虽有范围，却没有完成“定语从句修饰后ろめたさ”的应用决定。设计要求保留两侧证据，这一点已有；需要增加显式的边界选择状态和不完整原因。

## 5. 语法候选

### 实际结果

十段共 468 个语法 occurrence 左右（报告中的 `all` 合计），每段均有候选与 observed 混合。已经准确命中的代表规则有：

- p01 `発展せしめる` 的使役、过去 `た`；
- p03 `ふけっていようと` 的 `ている`、意志形和逆条件框架；
- p04 `支払わなければならない` 的义务构式；
- p05 `扱われます` 的受身与敬体成员；
- p08 `たとえ無意識とはいえ` 的呼应表达，以及 `ている`；
- p09 `覗かれてる` 的受身和 `ている` 缩约；
- p10 `専有してしまっている` 的 `てしまう + ている`。

### 日语和设计判断

形态特征层的 `past`、`te_form`、`negative`、`conditional`、`volitional` 等标签可作为证据。p04 的 `なければならない`、p08 的 `ている`、p10 的 `てしまっている` 等组合结果来自旧通用规则扫描器，只能证明词元表面序列能够命中，不能证明重构后的语法识别成立。

高层语法仍未达到设计目标。`selected` 通常只有 5-22 条，且其中大量是原子形态标签；`candidate` 与 `observed` 的比例接近一半，缺少 sense 选择、接续条件、捕获变量和反例校验。模型标签被引用为 evidence，但尚未转化为稳定的语义判断。

### 典型问题

- p01 的 `発展せしめる` 只显示 `しめる` 的使役命中，尚未给出文语使役“使……发展”的整体解释。
- p03 的 `ながら` 被命中为 `nagara_mo`，但句中是 `日向ぼこりをしながら` 的同时动作；`も` 属于后续呼应结构，不能由 `ながら` 单独决定完整义项。
- p04 的 `という` 只列为 candidate。法律条文中的 `「教科用拡大図書等」という` 是命名/引用构式，需要识别引号内名词短语与 `という` 的关系。
- p08 的 `たとえ…とはいえ` 已命中表达，但语法层没有把 `とはいえ` 的让步功能和前项范围绑定成同一实例。
- p09 的 `見渡すが` 只保留 `が` 的结构证据，逆接意义依赖后件 `気づかない`，当前没有生成完整逆接语法实例。
- p10 的 `という` 仍是 candidate；此处是同格/内容定语连接，不宜直接解释为普通引用“说”。

## 6. 表达匹配

### 实际结果

p01、p02、p04、p05、p06、p07、p09、p10 的表达数为 0；p03 有 1 条 `ふけっていようと` 相关构式；p08 有 1 条 `たとえ無意識とはいえ`。十段合计只有 2 条表达 occurrence。

### 日语和设计判断

已命中的两条在语义上基本合理：`たとえAとはいえ` 是让步呼应，`Vていようと` 在 p03 中形成“即使正在……也……”的让步条件。表达层已证明目录接口能够产生结果，但覆盖远未达到设计要求。

典型未识别包括 p01 `方向転換を行う`、p03 `一向に頓着しない`、p09 `覗かれてるとは気づかない`、p10 `比べ物にならない`、`後ろめたさが背筋を這い上がる`。其中 p10 的 `比べ物にならない` 和 p09 的 `とは気づかない` 具有明确的惯用/构式性质，不能以“没有表达规则”视为语料没有表达。

现有两条结果来自旧通用规则扫描器。扫描器以词元序列和简单 gap 条件决定命中，不能表达小句关系、句法角色、词汇义项和反例条件；表达层应标为“未完成接入”，两条输出不作为新架构的验收证据。

## 7. 阅读单位

### 实际结果

阅读单位数量与 token 数接近，但多数仍是原子 token；已确认整体词只在少数位置替代成员。p01 的 `方向転換`、p06 的 `神戸市`、p08 的 `満員電車`、p09 的 `見渡す`、p10 的 `這い上がる` 可以作为整体，p04/p07 的专业复合词则不稳定。

### 日语和设计判断

阅读单位能够覆盖正文并提供查询入口，基础导航可用。作为面向学习者的单位，它尚未满足“整体词优先、活用链归属明确、候选状态不误导”的目标。

最明显的问题是候选在未确认时改变了用户看到的切分：p01 `うち大正`、p04 `教科用 | の | 図書`、p07 `午後4`、`21日昼前` 都显示了由当前聚合策略造成的异常单位。数字、接尾词和复合词需要独立的规则层，不能以字符相邻或 provider 片段直接形成展示单位。

## 8. 解释和投影

### 实际结果

每段均有解释和投影。解释层按 grammar/morphology/structure 分层，p01-p10 的投影数量大于解释数量，通常为 67-400。p08 额外包含 expression 投影，其他段落只有语法、形态和结构投影。

### 日语和设计判断

范围定位和来源引用可用，投影没有脱离 occurrence 独立生成目标，符合 `projection` 只保存稳定引用的设计。解释数量说明系统已经能够为形态、结构和部分语法 occurrence 生成内容入口。

投影层当前忠实复制所有 occurrence，包括 candidate 和可能错误的形态解释。因此它适合调试和复核，不适合直接作为最终教学高亮。p04 的 `掲載された`、p05 的 `扱われます`、p09 的 `覗かれてる` 如果不经过义项消歧，投影会把“受身/可能”并列暴露；p02 的未知字形和 p07 的数字边界也会进入普通阅读单位。

## 后续优先级

1. 先完成活用链的 ownership 和组合：覆盖 `発展せしめる`、`掲載された`、`扱われます`、`覗かれてる`、`専有してしまっている`。
2. 为构词候选加入词典绑定、读音验证和冲突选择，优先处理 `教科用図書`、`線状降水帯`、`神戸市`、`方向転換`。
3. 将语法识别拆成“原子形态 → 构式候选 → sense 选择 → 解释投影”，补充受身/可能、`とはいえ`、`という`、`ながら`、`なければならない` 的正反例。
4. 重新设计表达识别，以词汇整体、活用链、基本句、小句和句法角色形成候选，再选择语义义项；先建立 `比べ物にならない`、`一向に頓着しない`、`とは気づかない`、`方向転換を行う` 的回归样例。
5. 阅读单位只接受已确认的整体或明确的候选状态，禁止候选直接覆盖词法边界；数字、接尾词和法律术语分别建立规则。
6. 投影按状态分层：`observed` 可进入默认高亮，`candidate/pending` 进入复核视图，避免将未完成判断显示为确定语法。

## 词典最长范围能力专项结论

### 能力定义

“尽可能扩大单词范围”至少包含三个连续步骤：从点击位置发现所有合理的连续词元范围；用表记、读音、词性和词典记录验证这些范围；在相互重叠的有效范围中选择语境允许的最长词汇整体，同时保留内部成分查询。当前系统只完成了部分候选验证，尚未形成这一完整能力。

### 当前调用链

`collect_dictionary_candidates` 只生成两类查询目标：每个 UniDic token，以及 formation 层已经提供的整体范围。它不会从某个 token 向左右枚举连续范围，也不会用词典反向发现 `n` 个词元组成的最长词条。formation 目前来自 GiNZA compound 和旧通用规则扫描；旧扫描移除后，未被 provider 提议的词汇整体不会进入词典验证。

`bind_lexical` 使用整体表记和拼接读音查询词典。查到记录且没有另一个已绑定的重叠候选时，范围标为 `observed`；两个重叠范围都有记录时标为 `pending`。查询引擎本身能够处理精确表记、别名、规范表记、读音和词性排序，适合作为范围验证器。

阅读单位的选择顺序存在错误：`reading_units` 在词典绑定之前生成，并从同一起点的 lexical candidate 中直接选择成员最多者，不检查 `observed/candidate/pending` 或 bindings。无词典记录的长候选也会覆盖原始 token 边界。前端 `App.vue` 点击后只发送 token ID；虽然后端保留 `QueryCandidate` 接口，当前界面没有使用 candidate ID 或 reading unit 的 `query_target_ids`，因此用户实际只能稳定查询单个 UniDic token。

### p01-p10 的实际程度

十段报告共有 80 个词汇范围决定：31 个 `observed`、47 个 `candidate`、2 个 `pending`。只有 38.75% 的范围完成了词典绑定且没有已绑定的竞争项；58.75% 没有整体词典记录；2.5% 存在多个可查范围而尚未选择。统计包含旧通用规则产生的候选，移除该模块后候选数量和覆盖面会下降，来源 compound 的准确率预计提高。

能够正确扩大并通过词典验证的典型例子：p01 `労働運動`、`政治運動`、`一転機`、`方向転換`；p03 `すねもの`、`哲学者`、`日向ぼこり`、`新聞記者`；p04 `複製物`、`教科用図書`、`著作物`；p06 `会社員`；p07 `気象庁`、`線状降水帯`；p08 `大多数`、`無意識`、`満員電車`；p09 `見渡す`；p10 `這い上がる`。系统对 provider 已给出准确范围、词典又存在整体记录的复合名词和复合动词表现较好。

能够提出范围但不能确认的典型例子：p02 `雲霧昂騰`、p05 `青空文庫`、p06 `神戸市`，以及 p07 的多组时间数字。专名、文语词和词典未收词会保持 candidate，这一状态本身合理；当前阅读单位仍采用这些范围，导致候选与确定结果在展示上混同。

范围明显错误的典型例子：p01 `うち大正`、`大正十`、`十四`、`四年`；p02 `ところ暑く`；p07 `20`、`0日`、`午後4`、`4時`、`時過ぎ`；p08 `東京市` 与 `市内` 的竞争。这些结果说明旧构词扫描和 provider 片段会生成跨越真实词界或截断数字表达的范围。当前“成员最多优先”可能选择其中较长者，不能视为最长词匹配。

p04 展示了系统的最佳能力和主要限制：`教科用図書` 能绑定一个整体词条，但同时与 `当該教科`、`教科用` 等范围竞争；`第二` 的多个重叠候选均有词典记录，状态为 pending。词典记录只能证明字符串可作为词条，不能单独决定本句应采用哪个范围。

### 结论

当前后端具备“验证已知整体候选”和“查询整体及内部 token”的数据基础，能够正确处理一部分由 GiNZA 提供的常见复合词。系统不具备从点击位置自动发现并选择最长有效词条的完整算法，当前桌面入口也没有接通整体候选查询。准确范围主要依赖 provider 偶然提供，旧规则候选显著引入错误边界。

后续实现应在每个点击位置枚举受句界、标点和词性连接约束的连续 token 范围，按长度从大到小调用词典验证；候选评分同时使用整体词条、拼接读音、词性兼容、provider compound、UniDic 构词字段和语境结构。只有已验证且竞争决定完成的范围进入默认阅读单位，其他范围留在复核视图。整体目标和内部 token 都应通过同一个后端查询目标协议提供给界面。
