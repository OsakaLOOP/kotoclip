# 词典与解释

本文定义下一模块的长期方案，待实施项目见 [TODO](TODO.md)，现状证据见 [P4 完成范围核对](p4_handoff.md)。P4 输出 token、活用链和构词候选；本模块负责词典验证、查询范围发现、聚合、竞争决定及用户查询目标。

## 查询目标

后端根据应用分析生成稳定的查询目标，包含实体引用、实际表记、候选查询形、对应读音、词性、上下文和词典绑定。阅读器、主动搜索、正文链接和导出使用同一查询服务。

| 目标 | 查询依据 |
| --- | --- |
| 词汇整体 | 已确认的整体形式及词典记录绑定 |
| 内部词形 | 命中位置所属活用链的查询形及对应读音 |
| 单个语素 | 出现表记、基本表记、词元及其字段证据 |
| 主动搜索 | 用户输入及明确的读音条件 |
| 词典链接 | 来源词典、目标记录或规范查询形式 |
| 语法说明 | occurrence、concept、sense 和本句捕获 |

整体与内部目标分别查询；两者等价时合并显示。语法说明拥有独立入口，可从说明中的词汇目标继续查词。

## 多粒度词汇查询

最终查询覆盖正文位置对应的整体词、内部子词、基本词元和功能成分。最粗粒度是上下文中有充分词汇依据的最大合理整体；最细粒度是仍具独立词汇或语法查询意义的成分。范围和引用表达包含关系，交叉候选及多个内部层次都可保留。

| 粒度 | 查询要求 | 代表验收对象 |
| --- | --- | --- |
| 整体词 | 结合构词与词典证据发现合理整体，保存规范形式、绑定和来源 | 方向転換、教科用図書、神戸市、満員電車 |
| 内部子词 | 同一位置可访问较小的词汇整体，保留中间层次 | 教科用図書中的教科用、教科、図書 |
| 基本词元 | 活用位置通向所属词汇核心的基本形，原子信息可查看 | 掲載された → 掲載する／掲載；読みませんでした → 読む |
| 功能成分 | 词汇查询与本句功能说明各自可达，缩约采用规范形式 | 覗かれてる中的いる与ている；読んでくださった中的くださる、过去形式 |
| token 内部词汇成分 | 来源 token 含多个有依据的成分时，提供精确范围和还原形式 | 見渡す、這い上がる的内部成分需逐词核验 |

最细粒度以人工确认的有意义成分验收。下一模块可生成独立的查询成分，记录范围、覆盖的 token、还原形式及词典／构词依据，来源 token 身份保持稳定。GiNZA A／B 诊断成分供核验，进入查询目标须有完整范围和词汇证据。人工选择文字沿用主动搜索，结果与自动词汇判断分别保存。

同范围的 token、构词和活用核心在词汇身份、读音及查询含义一致时共享查询结果。包含关系保留整体与成分入口，交叉关系保存备选和选择理由。补助链的父子关系表示功能接续，词汇包含关系表示查询粒度。

## 候选发现与词典决定

P4 的构词候选提供起点。模型未提出的词汇范围、内部子词及词典绑定由本模块发现和验证，结果引用 P4 对象和正文范围。依存候选保留实验性证据身份。

处理顺序为：读取当前位置的 token、链及构词，生成受边界约束的候选，进行词典索引查询和词形／读音校验，再组织默认目标、内部目标及备选。范围发现遵守标点、段落、空白和功能连接条件；惯用语及跨助词表达由后续表达模块结合词典、形态和结构证据组织独立目标。

默认选择同时考虑词汇依据、合法范围、上下文词性、读音和记录类型。整体命中后，内部对象继续可查。整体未命中时，区分词典未收录、读音冲突、范围不成立和执行错误，提供合理子词或基本词元。pending 范围须经核验才能成为默认目标。

来源观察、词汇采用、词典验证和界面选择分别保存。本模块拥有查询聚合与决定，P4 产物通过引用保留；词典新增证据触发本模块重算。

## 表记与读音

UniDic 查询形式按出现表记／`kana`、基本表记／`kanaBase`、词元／`lForm` 配对。活用链优先提供经过还原的查询形。缺少可靠读音时保留缺失状态，由表记与词典证据查询。

每本词典独立执行精确表记、词典内别名和必要的读音发现。读音用于表记与记录准入，词性提供排序和结构证据。明确冲突的读音进入诊断，缺少读音的记录结合表记及实质正文判断。

例如 `行く` 可对应 `いく` 和 `ゆく`：全局表记行保持统一，各词典单元格按本次读音装配记录。规范化只作用于查询键和分组身份，原始表记与各词典读音继续保留。

单 token 的字段读音、多个成员拼接的读音和词典确认读音分别保存依据。拼接读音作为待验证条件；发现冲突时通过表记及相应证据重新核验，保留冲突原因。同表记的不同读音候选保持独立。来源词元的分类后缀先按字段规则解释，再形成查询键。

活用链默认查询规范基本形，出现形作为上下文和有依据的备选。例如 `読みませんでした` 默认选择 `読む`，`読み` 的同形名词记录作为独立备选；`てる` 在补助链中默认选择 `いる`，语法说明对应 `ている`。规范显示使用基本形，原始成员保留缩略和浊化。

## 表记矩阵

查询结果采用“表记组 × 词典列 × 词典记录”的结构。表记组保留原始 variants、读音、证据和全部词典可用性；同一单元格可包含多个读音、词性或记录类型相容的 occurrence。

词典列及顺序由用户设置决定。活动表记加载实质正文，其余表记保存矩阵元数据。切换表记只改变选中的表记 ID，根查询、观察形式、读音和词性保持一致。

正文关系导航在当前面板建立查询历史；表记、词典和单元格内记录选择属于当前查询状态。整体与内部面板分别维护历史和请求代次。

一次目标查询的合法词形共同形成矩阵，每组保留自身表记 ID、读音和记录关联；默认表记按目标的词汇身份确定。候选查询传入实际出现形及核心词性，返回所选对象、备选、记录与理由。整体命中状态与各查询形式的验证结果分别报告。

## 目标版本与执行

正文查询统一携带会话、文本版本、任务代次、分析单元、产物版本及目标引用。整体、子词、token 和功能目标复用该校验入口；来源追加或重算后，用当前产物重新解析目标并结束过期响应。

候选范围限定在分析单元及合法词汇边界内，按范围与规范词汇身份去重；先查询轻量索引，再按选择加载正文。来源分析、词典实例和版本化缓存复用，词典或目标规则更新只重算本模块受影响结果。验证可按可见范围或实际查询触发，正文基础分析独立完成。

后端提供统一的多粒度目标供双面板和阅读投影消费。范围上限、缓存容量和耗时指标结合覆盖样本测量，短文本与长章节分别记录。UniDic 与 GiNZA 提供词汇主流程对象，KWJA 实验信息按需追加。

## 词典内容与存储

| 对象 | 职责 |
| --- | --- |
| `.kdict` | 分发和重建用源包，包含词头、索引关系及压缩释义 |
| schema v4 SQLite | 本机查询缓存，按源包身份校验并重建 |
| 词典 occurrence | 词典、源 entry 和子记录共同限定的稳定内容身份 |
| sense tree | 真实义项编号、层级、局部标签、释义和例句 |
| section 与 relation | 惯用句、派生、表记说明和正文参照关系 |

大辞林、小学馆和 Crown 分别由专用适配器解析。跨词典按表记组织查询，各词典的义项层级与标签保留自身作用域。正文渲染消费结构化内容；兼容 HTML 经过现有清洗与 CSP 约束。

源包变化使对应查询缓存更新。definition block 和 presentation 缓存分别管理，缓存键包含词典资源身份与适配器版本。用户画像和词典优先级独立持久化。

## 悬浮与显示

交互沿语义命中、状态判断、请求会话和最终显隐依次执行。用户悬浮词汇、成分或语法目标时，界面打开相应解释；已知状态与查询资格分别处理。

整体和内部面板使用独立请求通道，复用等价的已完成查询。响应校验请求 ID、目标、分析版本与词典资源版本。同一阅读单位内移动仅刷新发生变化的目标；锚点卸载或目标失效时结束会话。

正文与面板之间保留关闭宽限，进入面板继续阅读。布局根据视口空间选择上下方并限制高度；双面板协调定位、分别滚动。窄窗口、长词头、词典名称和多义项均保持组件边界内可操作。

## 验收与入口

验收覆盖同形异读、假名查询、别名、无正文记录、整体与内部切换、词典顺序、表记切换、链接返回和迟到响应。重点样本包括 `行く`、`強い／コワイ`、`警察署`、活用词及无整体词条的数量表达。

查询引擎位于 [lookup.rs](../crates/kotoclip-core/src/dictionary/lookup.rs)，矩阵状态位于 [lookup_state.rs](../crates/kotoclip-core/src/dictionary/lookup_state.rs)，内容协议位于 [model.rs](../crates/kotoclip-core/src/dictionary/model.rs)。[output.rs](../crates/kotoclip-core/src/output.rs)是当前应用输出接入点，[useExplanationSession.ts](../src/composables/useExplanationSession.ts)和[ExplanationPopover.vue](../src/components/explanation/ExplanationPopover.vue)提供解释会话与面板基础。
